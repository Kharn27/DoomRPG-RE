# MAPFLASH-V2 P5a — read-only early activation (pending CYD)

At the first successful default SD PAK open (boot asset validation), hash the existing validated index scan. Read and validate the committed raw header against that exact SD geometry/index FNV, hash the flash index and payload and run P4a CRCs before publishing a verified read-only active flash owner. No second SD open, no new persistent allocation, 4096 B transient scratch, no new format or partition. On success close SD File and switch this physical open to flash; subsequent default opens route through existing flash path. No target-map handoff proof is granted. Later gameplay prepare still performs its full verification and reuses CRC proof if identity matches; no relaxation of P2. If cache absent/corrupt/SD identity changed/flash read or allocation fails, continue existing SD startup open without erase/write, and defer rebuild to normal gameplay prepare. Attempt once per boot. Custom SD assets, saves, music untouched. No claim of total boot speedup: full FNV scan moved earlier and may be repeated; first load no longer performs first CRC scan on a healthy boot.

Host test extends P4b production extraction with healthy boot proof, mismatched index, corrupt payload, flash read failure and erased cache; assert zero writes and no target handoff. Source ordering checks verify validated SD index precedes boot route. Physical File close and startup call graph remain CYD validation.

CYD: keep PAK and flash, normal/inverted env as appropriate, no erase_flash. Expect P5a marker and CRC-PASS then BOOT-HIT before [DATA] Native PAK indexed; no erase/write, same menu frame hash if same theme; play music, open Options/Help, START or LOAD slot05, then actual Junction→Sector1, EXIT and reboot. Gameplay full HIT and CRC-REUSE, P2 HANDOFF and P3 zero SD payload remain. Log actual startup and loading times, RAM, audio; no intentional corruption. Cold no-cache path is host-tested only.
