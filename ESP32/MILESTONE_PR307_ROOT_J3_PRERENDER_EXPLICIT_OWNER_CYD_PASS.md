## Frontière supprimée

Le firmware avait déjà un propriétaire processus explicite `doomRpg` dans `ESP32/src/main.cpp`, mais `ESP32/src/esp_legacy_prerender_startup.c` utilisait encore `extern DoomRPG_t* doomRpg`. Désormais `EspLegacyPrerenderStartup_start(DoomRPG_t* root, int layoutReady)` prend ce token en argument et le transmet à `EspNativeMenuStorage_startup(..., root)`, sans lire le singleton global. Le header déclare le type `struct DoomRPG_s` de façon anticipée. Préconditions `layoutReady`, root, `menuSystem`, assets PAK `j.bmp`/`p.bmp`, et `preRenderAttempted` / `preRenderReady` restent inchangées et fail-closed. **Aucune allocation, world mutation, framebuffer, layout, PAK ou fonction SDL modifiée** pour J3 ; le processus identitaire 1 B et les contrats de teardown sont conservés. La garde Root-J2 inverse maintenant, à part et exactement, la modification du même `main.cpp` introduite par J3 avant de revérifier son blob d'origine ; elle ne change aucun code runtime.
